# 多表查询——联合查询

## 1. 联合查询概述

联合查询用于把多条 `SELECT` 语句的查询结果纵向合并，形成一个新的结果集。

联合查询使用以下关键字：

- `UNION`：合并结果并去除重复记录。
- `UNION ALL`：直接合并全部结果，保留重复记录。

## 2. 基本语法

```sql
SELECT 字段列表
FROM 表A
...

UNION [ALL]

SELECT 字段列表
FROM 表B
...;
```

也可以继续联合更多查询：

```sql
SELECT 字段列表 FROM 表A
UNION ALL
SELECT 字段列表 FROM 表B
UNION ALL
SELECT 字段列表 FROM 表C;
```

## 3. UNION

`UNION` 合并多个查询结果，并去除完全重复的记录。

```sql
SELECT name, phone
FROM current_customer

UNION

SELECT name, phone
FROM history_customer;
```

只有当结果行中所有字段的值都相同时，`UNION` 才会将其视为重复记录并去重。

## 4. UNION ALL

`UNION ALL` 合并多个查询的全部结果，不进行去重。

```sql
SELECT name, phone
FROM current_customer

UNION ALL

SELECT name, phone
FROM history_customer;
```

如果同一条数据同时出现在两次查询中，最终结果会保留两条记录。

## 5. UNION 与 UNION ALL 对比

| 对比项 | `UNION` | `UNION ALL` |
|---|---|---|
| 是否去重 | 是 | 否 |
| 是否保留重复记录 | 否 | 是 |
| 处理开销 | 较高，需要进行去重 | 较低，直接合并结果 |
| 适用场景 | 需要唯一结果 | 确定没有重复或允许重复 |

如果业务不需要去重，通常优先使用 `UNION ALL`。

## 6. 使用要求

参与联合查询的每条 `SELECT` 语句必须满足以下要求：

### 6.1 字段数量相同

以下写法错误，因为两次查询返回的字段数量不同：

```sql
-- 错误示例
SELECT id, name
FROM employee

UNION ALL

SELECT id, name, address
FROM customer;
```

### 6.2 对应字段类型兼容

相同位置的字段数据类型应当相同或能够相互转换。

```sql
SELECT id, name
FROM employee

UNION ALL

SELECT id, name
FROM customer;
```

字段按照位置进行匹配，而不是按照字段名匹配：

```sql
SELECT id, name
FROM employee

UNION ALL

SELECT customer_id, customer_name
FROM customer;
```

以上查询可以联合，因为两次查询返回的字段数量相同，且相同位置的类型兼容。

### 6.3 结果列名由第一次查询决定

最终结果集的列名取自第一条 `SELECT` 语句：

```sql
SELECT id AS 编号,
       name AS 姓名
FROM employee

UNION ALL

SELECT customer_id,
       customer_name
FROM customer;
```

最终结果的列名为“编号”和“姓名”。第二条查询中的字段名或别名不会改变最终列名。

## 7. 合并不同条件的同一张表

联合查询不要求使用不同的表，也可以合并对同一张表执行的多次查询。

查询年龄小于 20 岁或大于 50 岁的员工：

```sql
SELECT id, name, age
FROM employee
WHERE age < 20

UNION ALL

SELECT id, name, age
FROM employee
WHERE age > 50;
```

该示例也可以使用 `OR` 简化：

```sql
SELECT id, name, age
FROM employee
WHERE age < 20 OR age > 50;
```

是否使用联合查询，应根据查询含义、执行计划和可读性决定。

## 8. 标记数据来源

联合不同表的数据时，可以增加一个固定值字段来标记每条数据的来源：

```sql
SELECT id,
       name,
       '员工' AS 数据来源
FROM employee

UNION ALL

SELECT id,
       name,
       '客户' AS 数据来源
FROM customer;
```

两次查询都必须返回三个字段，并且相同位置的字段类型应兼容。

## 9. 排序与分页

对整个联合结果排序时，应在最后一条查询之后书写一次 `ORDER BY`：

```sql
SELECT id AS 编号,
       name AS 姓名
FROM employee

UNION ALL

SELECT id,
       name
FROM customer

ORDER BY 编号;
```

也可以对联合后的结果进行分页：

```sql
SELECT id AS 编号,
       name AS 姓名
FROM employee

UNION ALL

SELECT id,
       name
FROM customer

ORDER BY 编号
LIMIT 10;
```

最后的 `ORDER BY` 和 `LIMIT` 作用于整个联合结果集。

## 10. 联合查询与连接查询的区别

| 对比项 | 联合查询 | 连接查询 |
|---|---|---|
| 主要关键字 | `UNION`、`UNION ALL` | `JOIN` |
| 合并方向 | 纵向增加记录行 | 横向增加字段列 |
| 数据关系 | 多个结果集结构兼容 | 表之间存在可匹配的关联条件 |
| 字段数量要求 | 每个查询返回的字段数量必须相同 | 各表字段数量可以不同 |

## 11. 注意事项

- 联合查询按照字段位置匹配数据，而不是按照字段名称匹配。
- 每条查询返回的字段数量必须相同，对应位置的数据类型应兼容。
- `UNION` 判断重复时会比较结果行中的全部字段。
- `UNION` 去重通常会产生额外开销；不需要去重时应优先考虑 `UNION ALL`。
- 最终结果的列名由第一条 `SELECT` 语句决定。
- 对整个结果集排序时，只在联合查询末尾使用一次 `ORDER BY`。
- `UNION` 与 `UNION ALL` 混合使用时容易产生歧义，应使用括号明确查询组合，并确认去重范围。
