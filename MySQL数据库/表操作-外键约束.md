

## 1. 外键概述

外键用于在两张表之间建立联系，保证关联数据的一致性和完整性。

- **父表（主表）**：保存被引用的数据。
- **子表（从表）**：通过外键字段引用父表中的数据。
- **外键字段**：子表中用于引用父表主键或唯一键的字段。

例如，部门表是父表，员工表是子表；员工表的 `dept_id` 引用部门表的 `id`。

```text
department.id  ←  employee.dept_id
    父表主键          子表外键
```

外键约束可以阻止以下无效操作：

- 子表插入父表中不存在的关联值。
- 子表把外键更新为父表中不存在的值。
- 在仍被子表引用时，随意删除或修改父表中的关联数据。

## 2. 基本语法

### 2.1 创建表时添加外键

```sql
CREATE TABLE 子表名 (
    字段名 数据类型,
    ...,
    CONSTRAINT 外键名称
        FOREIGN KEY (外键字段)
        REFERENCES 父表名 (父表字段)
        [ON UPDATE 外键行为]
        [ON DELETE 外键行为]
);
```

### 2.2 修改表时添加外键

```sql
ALTER TABLE 子表名
ADD CONSTRAINT 外键名称
FOREIGN KEY (外键字段)
REFERENCES 父表名 (父表字段)
[ON UPDATE 外键行为]
[ON DELETE 外键行为];
```

## 3. 完整示例

先创建父表：

```sql
CREATE TABLE department (
    id   INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL
) ENGINE = InnoDB;
```

再创建子表并添加外键：

```sql
CREATE TABLE employee (
    id      INT PRIMARY KEY,
    name    VARCHAR(50) NOT NULL,
    dept_id INT,
    CONSTRAINT fk_employee_department
        FOREIGN KEY (dept_id)
        REFERENCES department(id)
) ENGINE = InnoDB;
```

测试外键约束：

```sql
INSERT INTO department (id, name)
VALUES (1, '研发部');

-- 成功：父表中存在 id 为 1 的部门
INSERT INTO employee (id, name, dept_id)
VALUES (101, '张三', 1);

-- 失败：父表中不存在 id 为 10 的部门
INSERT INTO employee (id, name, dept_id)
VALUES (102, '李四', 10);
```

## 4. 外键行为

当父表的关联数据被更新或删除时，可以通过 `ON UPDATE` 和 `ON DELETE` 指定对子表数据的处理方式。

| 外键行为 | 作用 |
|---|---|
| `RESTRICT` | 如果父表记录已被引用，则拒绝更新或删除父表记录 |
| `NO ACTION` | 在 MySQL 的 `InnoDB` 中效果与 `RESTRICT` 相同，也是立即拒绝操作 |
| `CASCADE` | 更新或删除父表记录时，自动更新或删除对应的子表记录 |
| `SET NULL` | 更新或删除父表记录时，将对应的子表外键设置为 `NULL` |
| `SET DEFAULT` | 将子表外键设置为默认值；`InnoDB` 不支持该行为 |

未指定外键行为时，MySQL 默认使用 `NO ACTION`，其效果与 `RESTRICT` 相同。

### 4.1 CASCADE：级联更新与删除

```sql
CONSTRAINT fk_employee_department
    FOREIGN KEY (dept_id)
    REFERENCES department(id)
    ON UPDATE CASCADE
    ON DELETE CASCADE
```

- 修改部门 `id` 时，员工表中的 `dept_id` 自动更新。
- 删除部门时，该部门下的员工记录也会被自动删除。

> `ON DELETE CASCADE` 可能一次删除大量关联数据，使用前应确认业务需求。

### 4.2 SET NULL：解除关联

```sql
CONSTRAINT fk_employee_department
    FOREIGN KEY (dept_id)
    REFERENCES department(id)
    ON UPDATE CASCADE
    ON DELETE SET NULL
```

删除部门后，相关员工的 `dept_id` 会变为 `NULL`，员工记录仍然保留。

> 使用 `SET NULL` 时，子表的外键字段必须允许为 `NULL`。

### 4.3 RESTRICT：阻止操作

```sql
CONSTRAINT fk_employee_department
    FOREIGN KEY (dept_id)
    REFERENCES department(id)
    ON UPDATE RESTRICT
    ON DELETE RESTRICT
```

只要部门仍被员工引用，就不能修改该部门的 `id`，也不能删除该部门。

## 5. 删除外键约束

删除外键时使用的是约束名称，而不是外键字段名称：

```sql
ALTER TABLE employee
DROP FOREIGN KEY fk_employee_department;
```

查看建表语句和外键名称：

```sql
SHOW CREATE TABLE employee;
```

外键删除后，为它创建的索引可能仍然存在。需要时可单独删除索引：

```sql
SHOW INDEX FROM employee;

ALTER TABLE employee
DROP INDEX 索引名称;
```

## 6. 联合外键

外键可以由多个字段共同组成。子表和父表中字段的数量及顺序必须对应。

```sql
CREATE TABLE course (
    school_id INT,
    course_id INT,
    name      VARCHAR(50),
    PRIMARY KEY (school_id, course_id)
);

CREATE TABLE course_selection (
    student_id INT,
    school_id  INT,
    course_id  INT,
    CONSTRAINT fk_selection_course
        FOREIGN KEY (school_id, course_id)
        REFERENCES course (school_id, course_id)
);
```

## 7. 创建外键的基本要求

- 通常应使用支持外键的 `InnoDB` 存储引擎。
- 父表必须先于子表创建；删除时通常先删除子表或外键，再删除父表。
- 被引用字段应为主键或唯一键，并建立索引。
- 子表外键字段与父表被引用字段的数据类型必须兼容；整数的长度、类型及 `UNSIGNED` 属性应保持一致。
- 字符串字段的字符集和排序规则应兼容。
- 联合外键两侧的字段数量、顺序和类型必须对应。
- 为已有表添加外键时，已有数据必须满足外键约束。
- 外键字段可以为 `NULL`；此时该行可以不关联父表记录，但字段必须允许为空。

## 8. 常见问题

### 8.1 无法插入或更新子表

常见报错：

```text
Cannot add or update a child row: a foreign key constraint fails
```

原因通常是子表外键值在父表中不存在。应先插入父表数据，再插入或更新子表数据。

### 8.2 无法删除或更新父表

常见报错：

```text
Cannot delete or update a parent row: a foreign key constraint fails
```

原因通常是父表记录仍被子表引用。可以根据业务需要：

- 先删除或修改相应的子表记录。
- 将子表外键设置为 `NULL`。
- 合理配置 `ON DELETE` 或 `ON UPDATE` 行为。

### 8.3 创建外键失败

应检查：

- 表名和字段名是否正确。
- 父表和子表是否使用支持外键的存储引擎。
- 两侧字段的数据类型、长度、符号属性是否兼容。
- 被引用字段是否具有合适的索引。
- 约束名称是否与当前数据库中的其他外键重名。
- 已有数据中是否存在无效的外键值。

## 9. FOREIGN_KEY_CHECKS

可以临时关闭当前会话的外键检查：

```sql
SET FOREIGN_KEY_CHECKS = 0;

-- 执行数据导入等操作

SET FOREIGN_KEY_CHECKS = 1;
```

关闭外键检查不会自动修复数据，也不应作为处理错误数据的常规方法。重新开启检查时，MySQL 不会自动扫描并验证关闭期间写入的所有数据，因此使用前必须确保数据一致性。

## 10. 设计建议

- 为外键显式命名，例如 `fk_子表_父表`，便于维护和删除。
- 根据业务含义选择外键行为，不要随意使用级联删除。
- 删除业务数据前，先确认是否存在多级级联关系。
- 既要使用外键保证数据完整性，也要在应用层做好参数校验和事务控制。
- 高频写入或复杂分库场景是否采用数据库外键，需要结合一致性要求、性能和架构统一评估。
