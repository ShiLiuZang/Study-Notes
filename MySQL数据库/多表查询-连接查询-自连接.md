# 多表查询——连接查询——自连接

## 1. 自连接概述

自连接是将同一张表当作两张或多张逻辑表进行连接查询。

自连接常用于查询表中数据之间的层级或关联关系，例如：

- 员工与直属领导。
- 分类与父分类。
- 地区与上级地区。
- 评论与被回复的评论。

自连接可以使用内连接，也可以使用外连接。

## 2. 基本语法

```sql
SELECT 字段列表
FROM 表A 别名A
JOIN 表A 别名B
    ON 连接条件;
```

虽然查询的是同一张物理表，但需要使用不同的别名把它看作两个不同角色的逻辑表。

## 3. 示例数据

员工表中的 `manager_id` 引用同一张表的 `id`，表示该员工直属领导的编号。

```sql
CREATE TABLE employee (
    id         INT PRIMARY KEY,
    name       VARCHAR(50) NOT NULL,
    manager_id INT,
    CONSTRAINT fk_employee_manager
        FOREIGN KEY (manager_id) REFERENCES employee(id)
);
```

示例数据：

| id | name | manager_id |
|---:|---|---:|
| 1 | 张总 | `NULL` |
| 2 | 李经理 | 1 |
| 3 | 王五 | 2 |
| 4 | 赵六 | 2 |

其中：

- 张总没有直属领导。
- 李经理的直属领导是张总。
- 王五和赵六的直属领导是李经理。

## 4. 自内连接

查询员工及其直属领导：

```sql
SELECT e.name AS 员工姓名,
       m.name AS 领导姓名
FROM employee e
INNER JOIN employee m
    ON e.manager_id = m.id;
```

别名代表的角色：

- `e`：员工。
- `m`：员工的直属领导。

自内连接只返回能够匹配到领导的员工。由于张总的 `manager_id` 为 `NULL`，所以查询结果中不会包含张总。

## 5. 自外连接

如果需要查询所有员工，包括没有直属领导的员工，可以使用左外连接：

```sql
SELECT e.name AS 员工姓名,
       m.name AS 领导姓名
FROM employee e
LEFT JOIN employee m
    ON e.manager_id = m.id;
```

此时张总也会出现在结果中，其领导姓名为 `NULL`。

可以使用 `IFNULL()` 提供更友好的显示内容：

```sql
SELECT e.name AS 员工姓名,
       IFNULL(m.name, '无直属领导') AS 领导姓名
FROM employee e
LEFT JOIN employee m
    ON e.manager_id = m.id;
```

## 6. 添加筛选条件

查询直属领导为“李经理”的员工：

```sql
SELECT e.name AS 员工姓名,
       m.name AS 领导姓名
FROM employee e
JOIN employee m
    ON e.manager_id = m.id
WHERE m.name = '李经理';
```

查询没有直属领导的员工：

```sql
SELECT e.id,
       e.name
FROM employee e
LEFT JOIN employee m
    ON e.manager_id = m.id
WHERE m.id IS NULL;
```

## 7. 多级自连接

同一张表可以连接多次。查询员工、直属领导和上级领导：

```sql
SELECT e.name AS 员工姓名,
       m.name AS 直属领导,
       gm.name AS 上级领导
FROM employee e
LEFT JOIN employee m
    ON e.manager_id = m.id
LEFT JOIN employee gm
    ON m.manager_id = gm.id;
```

三个别名分别表示：

- `e`：员工。
- `m`：直属领导。
- `gm`：直属领导的领导。

固定层数较少时可以使用多次自连接；层级数量不确定时，通常需要使用递归公共表表达式等方式处理。

## 8. 自连接与普通连接的区别

| 对比项 | 普通连接 | 自连接 |
|---|---|---|
| 参与查询的物理表 | 通常是不同的表 | 同一张表 |
| 是否需要别名 | 建议使用 | 必须使用不同别名区分角色 |
| 连接方式 | 可以是内连接或外连接 | 也可以是内连接或外连接 |
| 常见用途 | 查询不同实体之间的关系 | 查询同类数据之间的层级或关联关系 |

## 9. 注意事项

- 自连接不是一种新的 `JOIN` 类型，而是同一张表参与多次连接的用法。
- 必须为同一张表设置不同别名，否则无法区分各字段属于哪个逻辑角色。
- `SELECT`、`ON` 和 `WHERE` 中的字段都应使用表别名限定，避免歧义。
- 使用内连接时，没有匹配数据的记录会被过滤；需要保留这些记录时应使用左外连接。
- 多次自连接只能查询固定层数，且层数越多，SQL 越复杂。
- 应在关联字段（如 `manager_id`）上建立索引，以提高连接查询效率。
- 层级数据应避免形成循环关系，例如 A 的上级是 B，同时 B 的上级又是 A。
