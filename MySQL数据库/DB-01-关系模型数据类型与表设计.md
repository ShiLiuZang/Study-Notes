# DB-01：关系模型、数据类型与表设计

> 本节目标：从零理解 MySQL、数据库、表和关系，能够使用常用数据类型与约束创建项目表。`users`、`knowledge_bases`、`documents` 综合练习已经订正；约束的实际拒绝行为放到 DB-02 插入数据时验证。

## 1. MySQL、数据库与 SQL

- 数据：对事实的记录。
- 数据库：按照一定结构组织起来的数据集合。
- DBMS：负责保存、查询、修改、权限、一致性和并发控制的数据库管理系统。
- MySQL：关系型数据库管理系统，不是 SQL 语言本身。
- SQL：向关系型数据库下达查询和修改命令的语言。

记忆：

```text
MySQL = 执行和管理数据的软件
SQL   = 告诉 MySQL 如何操作数据的语言
```

在 Web 项目中：

```text
浏览器 → HTTP 请求 → FastAPI
FastAPI → 校验、授权、业务处理 → SQL/ORM
MySQL → 执行查询或修改 → 返回数据
FastAPI → HTTP 响应
```

## 2. 数据库基本操作

```sql
SHOW DATABASES;

CREATE DATABASE IF NOT EXISTS personal_knowledge_base
CHARACTER SET utf8mb4
COLLATE utf8mb4_0900_ai_ci;

USE personal_knowledge_base;

SELECT DATABASE();

SHOW CREATE DATABASE personal_knowledge_base;
```

`DROP DATABASE` 会删除整个数据库及其中的数据，不能把它当作“退出数据库”。

## 3. 表、行、列和值

```text
users 表

+----+----------+----------------+
| id | username | email          |
+----+----------+----------------+
| 1  | 小明     | xm@example.com |
| 2  | 小红     | xh@example.com |
+----+----------+----------------+
```

- 表：保存同一类对象的数据，例如用户。
- 列：这一类对象具有哪些属性，例如 `id`、`username`、`email`。
- 行：一条完整记录，例如一名具体用户。
- 值：某行某列中的具体内容，例如 `小明`。
- 行在结果中的位置不等于主键值，不能把“第二行”理解成 `id = 2`。

## 4. 创建和查看表

基本语法：

```sql
CREATE TABLE 表名 (
    列名 数据类型,
    列名 数据类型
);
```

示例：

```sql
CREATE TABLE notes (
    id BIGINT,
    title VARCHAR(100),
    content TEXT
);
```

查看表：

```sql
SHOW TABLES;
DESC notes;
SHOW CREATE TABLE notes;
```

语法习惯：

- SQL 关键字统一大写。
- 列之间使用英文逗号。
- 最后一列后不写逗号。
- SQL 语句以英文分号结束。
- 字符串使用单引号，例如 `'pending'`。
- SQL 中不能混入 Markdown 的 `*` 或反斜杠。

## 5. 当前项目常用数据类型

| 类型 | 主要用途 | 示例 |
| --- | --- | --- |
| `BIGINT` | 主键、外键和较大整数 | `id BIGINT` |
| `VARCHAR(n)` | 有明确最大长度的短文本 | `email VARCHAR(255)` |
| `TEXT` | 普通长文本 | `description TEXT` |
| `MEDIUMTEXT` | 容量更大的文档正文 | `raw_content MEDIUMTEXT` |
| `DECIMAL(M,D)` | 金额等精确小数 | `price DECIMAL(10,2)` |
| `BOOLEAN` | 布尔语义；MySQL 中是 `TINYINT(1)` 的别名 | `is_active BOOLEAN` |
| `DATE` | 只有年月日 | `birthday DATE` |
| `DATETIME(6)` | 日期时间和最多六位小数秒 | `created_at DATETIME(6)` |

`DECIMAL(M,D)`：

- `M` 是全部数字位数。
- `D` 是小数位数。
- 8 位整数加 2 位小数应使用 `DECIMAL(10,2)`。

时间选择：

- `DATE` 只保存日期。
- `DATETIME` 保存日期和时间，不进行 `TIMESTAMP` 那样的隐式连接时区转换。
- 本项目审计时间统一使用 `DATETIME(6)`，应用连接、写入和序列化统一明确为 UTC。
- `TIMESTAMP` 会在连接时区和 UTC 之间转换，且 MySQL 8.4 的范围比 `DATETIME` 小，本项目不把它作为统一审计字段类型。

## 6. NULL、默认值和基础约束

`NULL` 表示没有值或未知，不等于 `0`、`''`、空格或字符串 `'NULL'`。

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE
);
```

- `PRIMARY KEY`：唯一标识一行，非空且唯一。
- `AUTO_INCREMENT`：由 MySQL 生成递增主键；删除数据后不保证重新使用旧 ID。
- `NOT NULL`：禁止保存 `NULL`。
- `UNIQUE`：禁止重复值。
- `DEFAULT`：插入时未提供该列才使用默认值。

默认状态与时间：

```sql
status VARCHAR(20) NOT NULL DEFAULT 'pending',
created_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)
```

## 7. 表之间的关系

判断关系时从两个方向提问：一个 A 最多对应多少个 B，一个 B 最多对应多少个 A。

### 7.1 一对多

```text
users 1 ─── N knowledge_bases
knowledge_bases 1 ─── N documents
conversations 1 ─── N messages
```

外键通常放在“多”的一方：

```text
knowledge_bases.user_id → users.id
documents.knowledge_base_id → knowledge_bases.id
```

### 7.2 一对一

```text
users 1 ─── 1 user_profiles
```

子表外键还要增加唯一约束：

```sql
user_id BIGINT NOT NULL UNIQUE
```

只加外键仍然是一对多，不能保证一个用户最多一份资料。

### 7.3 多对多

文档和标签是多对多，需要中间表：

```text
documents 1 ─── N document_tags N ─── 1 tags
```

```sql
CREATE TABLE document_tags (
    document_id BIGINT NOT NULL,
    tag_id BIGINT NOT NULL,
    PRIMARY KEY (document_id, tag_id)
);
```

不要把多个 ID 保存成逗号分隔字符串。

## 8. 外键与删除策略

外键定义在子表上，用来保证引用的父记录存在：

```sql
CREATE TABLE documents (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    knowledge_base_id BIGINT NOT NULL,
    title VARCHAR(200) NOT NULL,

    CONSTRAINT fk_documents_knowledge_base
        FOREIGN KEY (knowledge_base_id)
        REFERENCES knowledge_bases(id)
        ON DELETE RESTRICT
);
```

对应关系：

```text
documents.knowledge_base_id → knowledge_bases.id
```

规则：

- 先创建父表，再创建子表。
- 父列和子列类型必须匹配，`BIGINT` 对应 `BIGINT`，`UNSIGNED` 属性也要一致。
- `RESTRICT`：仍被引用时拒绝删除父记录。
- `CASCADE`：删除父记录时自动删除子记录，必须谨慎使用。
- `SET NULL`：删除父记录时把外键置空，外键列必须允许 `NULL`。
- 不通过关闭外键检查来掩盖错误数据。

## 9. 联合唯一与 CHECK

同一用户不能创建两个同名知识库，但不同用户可以使用相同名称：

```sql
CONSTRAINT uq_knowledge_bases_user_name
    UNIQUE (user_id, name)
```

同一知识库中不能重复上传相同内容：

```sql
CONSTRAINT uq_documents_knowledge_base_content_hash
    UNIQUE (knowledge_base_id, content_hash)
```

状态值检查：

```sql
status VARCHAR(20) NOT NULL DEFAULT 'pending',

CONSTRAINT chk_documents_status
    CHECK (status IN ('pending', 'processing', 'ready', 'failed', 'deleting'))
```

边界：

- `CHECK` 限制允许出现哪些状态值。
- `pending → processing → ready` 等状态迁移由 service 层控制。
- `content_hash` 使用联合唯一约束，不能错误地拿它与状态字符串比较。

## 10. 建表规范

项目统一使用：

```sql
) ENGINE=InnoDB
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;
```

- InnoDB 提供事务、回滚、外键、行级锁和崩溃恢复等项目需要的能力。
- `utf8mb4` 支持完整 Unicode，包括中文和 Emoji。
- collation 决定文本比较和排序语义；`utf8mb4_0900_ai_ci` 通常不区分大小写和重音。
- 邮箱进入数据库前由应用执行 `strip()` 和 `lower()`，数据库再用唯一约束兜底。
- 使用严格 SQL mode，查看命令为 `SELECT @@SESSION.sql_mode;`。

命名：

- 表名使用复数和 `snake_case`，例如 `knowledge_bases`。
- 主键统一为 `id`。
- 外键使用 `对象_id`，例如 `knowledge_base_id`。
- 布尔字段使用 `is_` 或 `has_` 前缀。
- 约束使用 `pk_`、`fk_`、`uq_`、`chk_` 前缀。

审计与软删除字段：

```sql
created_at DATETIME(6) NOT NULL
    DEFAULT CURRENT_TIMESTAMP(6),

updated_at DATETIME(6) NOT NULL
    DEFAULT CURRENT_TIMESTAMP(6)
    ON UPDATE CURRENT_TIMESTAMP(6),

deleted_at DATETIME(6) NULL
```

活动数据查询需要明确：

```sql
WHERE deleted_at IS NULL
```

软删除适合需要恢复、审计或跨系统补偿的数据，不是每张表都必须添加。

## 11. 本轮易错点

- `SQL` 是语言，不是数据库。
- `DATABASE()` 是函数：`SELECT DATABASE();`。
- SQL 语句末尾要写英文分号。
- 字符串使用单引号。
- 使用英文括号和逗号，SQL 中不加入 Markdown 的 `*`、`\`。
- `DATETIME(6)` 的小数秒精度最大为 6。
- `BOOLEAN` 是类型，`CHECK (...)` 是约束，两者不是一回事。
- 外键语法是 `FOREIGN KEY (knowledge_base_id)`，括号中写子表外键，不写子表主键 `id`。
- 联合唯一约束与 `CHECK` 解决的是不同问题。

DB-01 阶段订正版：

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    email VARCHAR(255) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    created_at DATETIME(6) NOT NULL
        DEFAULT CURRENT_TIMESTAMP(6),
    updated_at DATETIME(6) NOT NULL
        DEFAULT CURRENT_TIMESTAMP(6)
        ON UPDATE CURRENT_TIMESTAMP(6)
) ENGINE=InnoDB
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

CREATE TABLE knowledge_bases (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    name VARCHAR(100) NOT NULL,
    description TEXT,
    created_at DATETIME(6) NOT NULL
        DEFAULT CURRENT_TIMESTAMP(6),
    updated_at DATETIME(6) NOT NULL
        DEFAULT CURRENT_TIMESTAMP(6)
        ON UPDATE CURRENT_TIMESTAMP(6),

    CONSTRAINT uq_knowledge_bases_user_name
        UNIQUE (user_id, name),
    CONSTRAINT fk_knowledge_bases_user
        FOREIGN KEY (user_id)
        REFERENCES users(id)
        ON DELETE RESTRICT
) ENGINE=InnoDB
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

CREATE TABLE documents (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    knowledge_base_id BIGINT NOT NULL,
    title VARCHAR(200) NOT NULL,
    raw_content MEDIUMTEXT NOT NULL,
    content_hash VARCHAR(64) NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'pending',
    created_at DATETIME(6) NOT NULL
        DEFAULT CURRENT_TIMESTAMP(6),
    updated_at DATETIME(6) NOT NULL
        DEFAULT CURRENT_TIMESTAMP(6)
        ON UPDATE CURRENT_TIMESTAMP(6),
    deleted_at DATETIME(6) NULL,

    CONSTRAINT uq_documents_knowledge_base_content_hash
        UNIQUE (knowledge_base_id, content_hash),
    CONSTRAINT chk_documents_status
        CHECK (
            status IN ('pending', 'processing', 'ready', 'failed', 'deleting')
        ),
    CONSTRAINT fk_documents_knowledge_base
        FOREIGN KEY (knowledge_base_id)
        REFERENCES knowledge_bases(id)
        ON DELETE RESTRICT
) ENGINE=InnoDB
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;
```

DB-02 使用这些表插入正常和非法种子数据，验证重复邮箱、重复知识库名称、重复文档、非法状态与无效外键确实被数据库拒绝。其余五张累计项目表在后续查询需求明确后逐步建立，并在 DB-08 冻结完整八表设计。
