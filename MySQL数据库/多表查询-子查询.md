# 多表查询——子查询

## 1. 子查询概述

SQL 语句中嵌套的 `SELECT` 查询称为嵌套查询，也称为子查询。

```sql
SELECT *
FROM t1
WHERE column1 = (
    SELECT column1
    FROM t2
);
```

- 外部的 SQL 语句称为主查询或外层查询。
- 内部的 `SELECT` 语句称为子查询或内层查询。
- 子查询可以继续嵌套其他子查询。

子查询外部的语句可以是 `SELECT`、`INSERT`、`UPDATE` 或 `DELETE`。

## 2. 子查询分类

### 2.1 按查询结果分类

| 类型 | 子查询结果 | 常用操作符 |
|---|---|---|
| 标量子查询 | 单个值，即一行一列 | `=`、`<>`、`>`、`>=`、`<`、`<=` |
| 列子查询 | 一列多行 | `IN`、`NOT IN`、`ANY`、`SOME`、`ALL` |
| 行子查询 | 一行多列 | `=`、`<>`、`IN`、`NOT IN` |
| 表子查询 | 多行多列 | `IN`，或放在 `FROM` 后作为派生表 |

### 2.2 按出现位置分类

子查询可以出现在：

- `WHERE` 或 `HAVING` 之后：作为筛选条件。
- `FROM` 之后：作为一张临时结果表，即派生表。
- `SELECT` 之后：作为查询结果中的一列。

### 2.3 按是否依赖外层查询分类

- **非相关子查询**：子查询能够独立执行，不引用外层查询中的字段。
- **相关子查询**：子查询引用外层查询中的字段，需要针对外层查询的记录进行关联判断。

## 3. 标量子查询

标量子查询返回一个值，即一行一列。

查询工资高于平均工资的员工：

```sql
SELECT id, name, salary
FROM employee
WHERE salary > (
    SELECT AVG(salary)
    FROM employee
);
```

查询与“张三”属于同一部门的员工：

```sql
SELECT id, name, dept_id
FROM employee
WHERE dept_id = (
    SELECT dept_id
    FROM employee
    WHERE name = '张三'
);
```

> 使用单值比较运算符时，子查询必须最多返回一行。返回多行会产生“Subquery returns more than 1 row”错误。

## 4. 列子查询

列子查询返回一列多行，常与 `IN`、`ANY`、`SOME` 和 `ALL` 配合使用。

### 4.1 IN

查询属于“研发部”或“市场部”的员工：

```sql
SELECT id, name, dept_id
FROM employee
WHERE dept_id IN (
    SELECT id
    FROM department
    WHERE name IN ('研发部', '市场部')
);
```

### 4.2 ANY 或 SOME

`ANY` 与 `SOME` 含义相同，只要满足子查询结果中的任意一个值即可。

查询工资高于 1 号部门任意一名员工工资的员工：

```sql
SELECT id, name, salary
FROM employee
WHERE salary > ANY (
    SELECT salary
    FROM employee
    WHERE dept_id = 1
);
```

`> ANY` 相当于大于子查询结果中的最小值，但使用时还要考虑空结果和 `NULL`。

### 4.3 ALL

`ALL` 表示必须满足子查询结果中的所有值。

查询工资高于 1 号部门所有员工工资的员工：

```sql
SELECT id, name, salary
FROM employee
WHERE salary > ALL (
    SELECT salary
    FROM employee
    WHERE dept_id = 1
);
```

`> ALL` 相当于大于子查询结果中的最大值，但使用时还要考虑空结果和 `NULL`。

## 5. 行子查询

行子查询返回一行多列，可以把多个字段作为一个整体进行比较。

查询与“张三”的部门和工资都相同的员工：

```sql
SELECT id, name, dept_id, salary
FROM employee
WHERE (dept_id, salary) = (
    SELECT dept_id, salary
    FROM employee
    WHERE name = '张三'
);
```

查询结果中如需排除张三本人，可以继续添加条件：

```sql
SELECT id, name, dept_id, salary
FROM employee
WHERE (dept_id, salary) = (
    SELECT dept_id, salary
    FROM employee
    WHERE name = '张三'
)
  AND name <> '张三';
```

## 6. 表子查询

表子查询返回多行多列，通常放在 `FROM` 子句中作为派生表使用。

查询每个部门中平均工资高于 8000 的部门：

```sql
SELECT t.dept_id,
       t.avg_salary
FROM (
    SELECT dept_id,
           AVG(salary) AS avg_salary
    FROM employee
    GROUP BY dept_id
) AS t
WHERE t.avg_salary > 8000;
```

MySQL 中，`FROM` 后的派生表必须设置别名，例如这里的 `t`。

表子查询也可以和其他表连接：

```sql
SELECT d.name AS 部门名称,
       t.employee_count AS 员工数量
FROM department d
JOIN (
    SELECT dept_id,
           COUNT(*) AS employee_count
    FROM employee
    GROUP BY dept_id
) AS t
    ON d.id = t.dept_id;
```

## 7. SELECT 后的子查询

子查询可以作为结果集中的一列，但该子查询必须返回标量值。

查询每个部门及其员工人数：

```sql
SELECT d.id,
       d.name,
       (
           SELECT COUNT(*)
           FROM employee e
           WHERE e.dept_id = d.id
       ) AS employee_count
FROM department d;
```

其中子查询引用了外层查询的 `d.id`，因此这是相关子查询。

## 8. EXISTS 与相关子查询

`EXISTS` 用于判断子查询是否至少返回一条记录，只关心记录是否存在，不关心具体字段值。

查询至少拥有一名员工的部门：

```sql
SELECT d.id, d.name
FROM department d
WHERE EXISTS (
    SELECT 1
    FROM employee e
    WHERE e.dept_id = d.id
);
```

查询没有员工的部门：

```sql
SELECT d.id, d.name
FROM department d
WHERE NOT EXISTS (
    SELECT 1
    FROM employee e
    WHERE e.dept_id = d.id
);
```

`SELECT 1` 表示只判断记录是否存在。写成 `SELECT *` 通常也能得到相同的逻辑结果。

## 9. 在 UPDATE 和 DELETE 中使用子查询

### 9.1 UPDATE

将研发部员工的奖金设置为工资的 10%：

```sql
UPDATE employee
SET bonus = salary * 0.1
WHERE dept_id = (
    SELECT id
    FROM department
    WHERE name = '研发部'
);
```

### 9.2 DELETE

删除已被标记为停用部门中的员工：

```sql
DELETE FROM employee
WHERE dept_id IN (
    SELECT id
    FROM department
    WHERE status = '停用'
);
```

执行更新或删除前，建议先使用相同条件执行 `SELECT`，确认受影响的数据范围。

## 10. 子查询与连接查询

同一需求有时既可以使用子查询，也可以使用连接查询。

使用子查询：

```sql
SELECT id, name
FROM employee
WHERE dept_id IN (
    SELECT id
    FROM department
    WHERE name = '研发部'
);
```

使用连接查询：

```sql
SELECT e.id, e.name
FROM employee e
JOIN department d
    ON e.dept_id = d.id
WHERE d.name = '研发部';
```

选择方式时可以考虑：

- 子查询有时更接近“先查询内部结果，再筛选外部数据”的思考方式。
- 连接查询适合同时获取多张表的字段，逻辑关系通常更加直观。
- 具体性能取决于索引、数据量和优化器执行计划，应使用 `EXPLAIN` 分析，不能简单认为某一种写法一定更快。

## 11. 常见问题与注意事项

- 使用 `=`、`>` 等单值比较运算符时，子查询不能返回多行；多行结果应根据需求使用 `IN`、`ANY`、`ALL` 或改写查询。
- `FROM` 后的子查询必须设置别名。
- 子查询返回的字段数量必须与外层比较表达式要求的字段数量一致。
- `NOT IN` 的子查询结果如果包含 `NULL`，整个判断可能变为未知，从而得不到预期结果；此时优先考虑过滤 `NULL` 或使用 `NOT EXISTS`。
- 相关子查询会引用外层字段，应确保关联字段具有合适的索引。
- 子查询嵌套过深会降低可读性，可以考虑连接查询或公共表表达式。
- 不要依赖子查询结果的默认顺序；需要排序时应在最终结果中明确使用 `ORDER BY`。
- 对修改和删除语句使用子查询时，应先确认影响范围，并在重要操作中使用事务。
