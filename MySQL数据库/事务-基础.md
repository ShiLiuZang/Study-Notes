# 事务——基础

## 1. 事务概述

事务是一组不可分割的数据库操作，这些操作要么全部成功，要么全部失败。

事务适合处理具有完整业务逻辑的一组操作，例如银行转账：

1. 从账户 A 扣款。
2. 向账户 B 加款。

如果只执行其中一步，数据就会不一致，因此这两步应放在同一个事务中。

> MySQL 8.4 默认使用 `InnoDB` 存储引擎。`InnoDB` 支持事务、提交、回滚和崩溃恢复。

## 2. 事务的四大特性：ACID

| 特性 | 英文 | 含义 |
|---|---|---|
| 原子性 | Atomicity | 事务中的操作是一个整体，要么全部完成，要么全部撤销 |
| 一致性 | Consistency | 事务执行前后，数据都应满足约束和业务规则，数据库从一个一致状态转变为另一个一致状态 |
| 隔离性 | Isolation | 并发执行的事务相互隔离，一个事务的中间状态不应被其他事务随意干扰 |
| 持久性 | Durability | 事务提交后，对数据的修改会被永久保存，即使系统发生故障也应能够恢复 |

`InnoDB` 主要通过以下机制实现事务特性：

- Undo Log：支持回滚和多版本并发控制。
- Redo Log：支持事务持久性和崩溃恢复。
- 锁：协调多个事务对相同数据的并发访问。
- MVCC：让许多普通查询通过数据版本实现一致性读取，减少读写冲突。
- 数据库约束与应用业务规则：共同保证数据一致性。

## 3. 事务控制语句

| 语句 | 作用 |
|---|---|
| `START TRANSACTION` | 开启事务 |
| `BEGIN` | 开启事务，是 `START TRANSACTION` 的别名 |
| `COMMIT` | 提交事务，使修改永久生效 |
| `ROLLBACK` | 回滚事务，撤销尚未提交的修改 |

基本语法：

```sql
START TRANSACTION;

-- 执行一组 DML 操作

COMMIT;
```

发生错误时回滚：

```sql
START TRANSACTION;

-- 执行一组 DML 操作

ROLLBACK;
```

## 4. 转账示例

创建账户表：

```sql
CREATE TABLE account (
    id      INT PRIMARY KEY,
    name    VARCHAR(50) NOT NULL,
    balance DECIMAL(12, 2) NOT NULL,
    CONSTRAINT chk_account_balance CHECK (balance >= 0)
) ENGINE = InnoDB;
```

从账户 1 向账户 2 转账 500 元：

```sql
START TRANSACTION;

UPDATE account
SET balance = balance - 500
WHERE id = 1;

UPDATE account
SET balance = balance + 500
WHERE id = 2;

COMMIT;
```

如果执行过程中出现异常，应执行：

```sql
ROLLBACK;
```

实际业务还需要在扣款前锁定并检查账户和余额。例如：

```sql
START TRANSACTION;

SELECT id, balance
FROM account
WHERE id IN (1, 2)
ORDER BY id
FOR UPDATE;

-- 应用程序确认两个账户存在，并且账户 1 的余额充足

UPDATE account
SET balance = balance - 500
WHERE id = 1;

UPDATE account
SET balance = balance + 500
WHERE id = 2;

COMMIT;
```

`FOR UPDATE` 会对读取的相关记录加排他锁，锁通常保持到事务提交或回滚。

## 5. 自动提交

MySQL 默认开启自动提交模式。未显式开启事务时，每条成功执行的 SQL 语句会作为一个独立事务自动提交。

查看当前会话的自动提交状态：

```sql
SELECT @@autocommit;
```

- 返回 `1`：自动提交已开启。
- 返回 `0`：自动提交已关闭。

关闭当前会话的自动提交：

```sql
SET autocommit = 0;
```

开启当前会话的自动提交：

```sql
SET autocommit = 1;
```

推荐在需要执行多语句事务时显式使用：

```sql
START TRANSACTION;
-- 业务操作
COMMIT;
```

`START TRANSACTION` 只会临时进入显式事务。执行 `COMMIT` 或 `ROLLBACK` 后，自动提交会恢复为事务开始前的状态。

## 6. 保存点

保存点可以在事务内部设置一个标记，只回滚保存点之后的操作，而不回滚整个事务。

| 语句 | 作用 |
|---|---|
| `SAVEPOINT 保存点名` | 创建保存点 |
| `ROLLBACK TO SAVEPOINT 保存点名` | 回滚到指定保存点 |
| `RELEASE SAVEPOINT 保存点名` | 删除指定保存点 |

示例：

```sql
START TRANSACTION;

UPDATE account
SET balance = balance - 500
WHERE id = 1;

SAVEPOINT after_deduction;

UPDATE account
SET balance = balance + 500
WHERE id = 2;

-- 只撤销保存点之后的操作
ROLLBACK TO SAVEPOINT after_deduction;

-- 最终仍需提交或回滚整个事务
ROLLBACK;
```

注意：

- `ROLLBACK TO SAVEPOINT` 不会结束当前事务。
- `COMMIT` 或完整的 `ROLLBACK` 会结束事务，并删除该事务中的所有保存点。
- 使用相同名称创建新保存点时，原有同名保存点会被替换。

## 7. 并发事务问题

多个事务同时读写相同数据时，可能出现以下问题。

### 7.1 脏读

一个事务读取了另一个事务尚未提交的数据。如果另一个事务随后回滚，之前读取到的数据就是无效的。

```text
事务 A：修改余额（尚未提交）
事务 B：读取到修改后的余额
事务 A：回滚
事务 B：曾读取到不存在的结果
```

### 7.2 不可重复读

同一个事务先后读取同一条记录，结果不同。原因通常是另一个事务在两次读取之间更新并提交了该记录。

```text
事务 A：读取余额为 1000
事务 B：把余额改为 800 并提交
事务 A：再次读取余额为 800
```

### 7.3 幻读

同一个事务使用相同条件进行范围查询，先后得到的记录数量不同。原因通常是另一个事务插入或删除了满足条件的记录并提交。

```text
事务 A：查询年龄大于 30 岁的员工，共 5 条
事务 B：插入一条满足条件的记录并提交
事务 A：再次执行相同范围查询，出现第 6 条记录
```

### 7.4 丢失更新

两个事务都读取同一数据并分别修改，后提交的修改覆盖了先提交的结果，导致其中一次更新丢失。

常见防护方式：

- 使用 `SELECT ... FOR UPDATE` 悲观锁。
- 使用版本号或时间戳实现乐观锁。
- 使用原子更新表达式，例如 `SET balance = balance - 500`，避免先读后写的竞争窗口。

## 8. 事务隔离级别

隔离级别用于平衡数据一致性与并发性能。隔离级别越高，并发事务之间的隔离越严格，但等待和锁竞争通常也可能越多。

`InnoDB` 支持四种隔离级别：

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 特点 |
|---|---|---|---|---|
| `READ UNCOMMITTED` | 可能 | 可能 | 可能 | 隔离性最低，普通读取可能看到未提交数据 |
| `READ COMMITTED` | 避免 | 可能 | 可能 | 每次一致性读取都会创建新的快照 |
| `REPEATABLE READ` | 避免 | 避免 | 见下方说明 | `InnoDB` 默认级别，同一事务中的普通一致性读取通常使用同一快照 |
| `SERIALIZABLE` | 避免 | 避免 | 避免 | 隔离性最高，使并发事务的效果接近串行执行 |

> 按 SQL 标准，`REPEATABLE READ` 仍可能出现幻读；`InnoDB` 通过 MVCC 的一致性读取以及锁定读取中的间隙锁、临键锁等机制，在常见场景中抑制幻读。普通快照读和当前/锁定读的行为不同，不能只用一张简单表概括所有情况。

MySQL `InnoDB` 的默认隔离级别是：

```text
REPEATABLE READ
```

## 9. 查看与设置隔离级别

查看当前会话的隔离级别：

```sql
SELECT @@transaction_isolation;
```

设置当前会话后续事务的隔离级别：

```sql
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

设置下一个事务的隔离级别：

```sql
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;

START TRANSACTION;
-- 事务操作
COMMIT;
```

四种隔离级别的完整写法：

```sql
SET SESSION TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
SET SESSION TRANSACTION ISOLATION LEVEL SERIALIZABLE;
```

修改隔离级别前应评估业务一致性要求、锁竞争和执行性能。
