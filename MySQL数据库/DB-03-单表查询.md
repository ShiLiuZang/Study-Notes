# DB-03：单表查询

> 本节目标：从一张表中选择列、筛选行、去重、排序和分页，并能写出包含软删除条件的稳定列表查询。

## 1. SELECT 与别名

只选择需要的列：

```sql
SELECT id, title, status
FROM documents;
```

使用 `AS` 设置结果列名：

```sql
SELECT
    id,
    title AS document_title
FROM documents;
```

`AS` 只改变查询结果中的显示名称，不会修改表结构或原始列名。业务查询优先明确列名，不依赖 `SELECT *`。

## 2. DISTINCT 去重

查询不同的文档状态：

```sql
SELECT DISTINCT status
FROM documents;
```

`DISTINCT` 去除的是所选列组合的重复：

```sql
SELECT DISTINCT title, status
FROM documents;
```

这里判断 `(title, status)` 组合是否重复，而不是分别对两列去重。

## 3. WHERE 与比较运算符

```sql
SELECT id, title
FROM documents
WHERE status = 'ready';
```

常用比较运算符：

```text
=           等于
!= 或 <>    不等于
>、>=       大于、大于等于
<、<=       小于、小于等于
```

字符串不等于：

```sql
WHERE status <> 'pending'
```

`IS` 主要用于 `NULL` 等特殊判断，普通字符串不能写成 `status NOT IS 'pending'`。

## 4. AND、OR 与括号

`AND` 要求条件同时成立，`OR` 要求至少一个条件成立：

```sql
SELECT id, title, status
FROM documents
WHERE (status = 'ready' OR status = 'pending')
  AND id >= 3;
```

`AND` 的优先级高于 `OR`。混用时应使用括号直接表达业务含义，避免依赖记忆优先级。

## 5. IN、NOT IN 与 BETWEEN

多个“等于”条件可以写成 `IN`：

```sql
WHERE status IN ('pending', 'processing')
```

排除列表中的值：

```sql
WHERE status NOT IN ('failed', 'deleting')
```

二者含义不同：`IN` 是明确只允许列出的值，`NOT IN` 是允许除所列值之外的其他值。

范围查询：

```sql
WHERE id BETWEEN 2 AND 4
```

`BETWEEN` 包含两端，等价于 `id >= 2 AND id <= 4`。

## 6. LIKE 模糊匹配

```text
%   任意数量的字符，包括零个字符
_   任意一个字符
```

常用模式：

```sql
-- 包含 MySQL
WHERE title LIKE '%MySQL%'

-- 以 MySQL 开头
WHERE title LIKE 'MySQL%'

-- 以“基础”结尾
WHERE title LIKE '%基础'
```

`'%MySQL%'` 和 `'MySQL%'` 可能在当前测试数据上得到相同结果，但业务含义不同。当前项目的 `utf8mb4_0900_ai_ci` 排序规则通常不区分英文大小写，实际匹配语义由字段 collation 决定。

## 7. NULL 判断与软删除过滤

`NULL` 不是普通值，必须使用：

```sql
WHERE deleted_at IS NULL
WHERE deleted_at IS NOT NULL
```

不能使用：

```sql
WHERE deleted_at = NULL
WHERE deleted_at != NULL
```

项目中的活动文档查询通常都要包含：

```sql
WHERE deleted_at IS NULL
```

`created_at IS NULL` 表示没有创建时间，不表示尚未删除；当前表还通过 `NOT NULL` 保证创建时间必填。

## 8. ORDER BY 与稳定排序

```sql
ORDER BY id ASC
ORDER BY id DESC
```

- `ASC`：升序，也是默认值。
- `DESC`：降序。

按最新创建时间稳定排序：

```sql
ORDER BY created_at DESC, id DESC
```

先按创建时间排序；时间相同时，再使用唯一的 `id` 决定顺序。分页查询必须有稳定排序，否则连续翻页可能出现重复或遗漏。

## 9. LIMIT 与 OFFSET

```sql
LIMIT 每页数量 OFFSET 跳过数量
```

第 3 页、每页 2 条：

```text
offset = (3 - 1) × 2 = 4
```

```sql
SELECT id, title, created_at
FROM documents
WHERE deleted_at IS NULL
ORDER BY created_at DESC, id DESC
LIMIT 2 OFFSET 4;
```

不要把页码直接写成 `OFFSET`，也不要把 `LIMIT` 和 `OFFSET` 的含义写反。

## 10. 查询表达式

`SELECT` 可以计算结果，计算列不会被保存到表中：

```sql
SELECT
    id,
    title,
    CHAR_LENGTH(title) AS title_length
FROM documents
WHERE deleted_at IS NULL
ORDER BY title_length DESC, id DESC;
```

这里 `title_length` 是别名。定义和使用必须一致，不能定义为 `display_title` 后又按 `title_length` 排序。

## 11. 书写顺序与逻辑执行顺序

常见书写顺序：

```text
SELECT → FROM → WHERE → ORDER BY → LIMIT/OFFSET
```

大致逻辑处理顺序：

```text
FROM → WHERE → SELECT → DISTINCT → ORDER BY → LIMIT/OFFSET
```

因此：

- `WHERE` 通常不能使用当前 `SELECT` 才定义的别名。
- `ORDER BY` 位于 `SELECT` 之后，通常可以使用结果别名。

```sql
SELECT status AS document_status
FROM documents
WHERE status = 'ready'
ORDER BY document_status;
```

## 12. 综合查询

```sql
SELECT id, title, status, created_at
FROM documents
WHERE deleted_at IS NULL
  AND status IN ('ready', 'processing')
  AND (
      title LIKE '%MySQL%'
      OR title LIKE '%Python%'
  )
ORDER BY created_at DESC, id DESC
LIMIT 3;
```

这条查询综合使用了软删除过滤、`IN`、`LIKE`、`AND/OR` 括号、稳定排序和数量限制。

## 13. 本轮易错点

- 把原表的 4 行误认为 `DISTINCT status` 也一定返回 4 行。
- 把 `id > 1` 写成 `id >= 1`。
- 漏写 `FROM documents`。
- 题目要求 `IN` 时写成含义更宽的 `NOT IN`。
- 把“包含”写成只匹配开头的 `LIKE 'MySQL%'`。
- 把字符串不等于写成无效的 `NOT IS`。
- 把 `deleted_at IS NULL` 误写成 `created_at IS NULL`。
- 把排序条件写进 `WHERE`，没有使用 `ORDER BY`。
- 把 `LIMIT` 和 `OFFSET` 的含义写反。
- 定义别名后，排序时使用了另一个不存在的别名。
- 综合查询中容易漏掉软删除过滤条件。

识别方法：写完查询后按“选哪些列、从哪张表、保留哪些行、怎样排序、取多少行”逐段检查。
